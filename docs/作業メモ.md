## (A) ライブラリ・クラス取捨選択

| 分類                                | 採用 / 不要 | 理由・用途                                                                  |
| --------------------------------- | ------- | ---------------------------------------------------------------------- |
| **three.js (core)**               | **採用**  | 描画の柱。`BoxGeometry` `ExtrudeGeometry` `Shape` `BufferGeometryUtils` を多用 |
| **three-csg-ts**                  | **採用**  | 丸穴・四角穴・断面加工など “切り抜く/足す” 処理に必須                                          |
| **RoundedBoxGeometry**            | **不要**  | 側面を直角に保ちづらい。平面 Shape＋Extrude の方が柔軟                                     |
| **LatheGeometry, TubeGeometry 等** | 不要      | 今回の形状には過剰                                                              |
| **three/examples テクスチャローダー類**     | 任意      | 木目テクスチャを使う場合のみ (`TextureLoader` は core に有り)                            |
| **three-mesh-bvh**                | 将来検討    | 穴・CSG が増えて描画が重くなったら導入 (加速構造による高速化)                                     |

## (B) 推奨実装ステップ

### STEP 0 基盤を整理

1. **importmap** に three.js と three-csg-ts を pin 済みか確認

   ```erb
   <%= pin "three", to: "https://unpkg.com/three@0.176.0/build/three.module.js" %>
   <%= pin "three-csg-ts" %>
   ```
2. **helpers/modifiers.js** に共通ユーティリティ（Shape→Extrude、CSG 操作、単位変換など）を集約
3. **Stimulus controller (`part3d`)** では「ctx を作る → モディファイアをパイプする」だけに絞る

---

### STEP 1 “平面形状ビルダー” を作る

* `buildBaseShape(ctx)`

  * `ctx.shape_code` で分岐し、下記いずれかを返す

    | shape\_code              | 実装                                         | 備考 |
    | ------------------------ | ------------------------------------------ | -- |
    | RECT, ROUND\_R など矩形系     | `THREE.Shape` を手書き（角Ｒは `quadraticCurveTo`） |    |
    | TRIANGLE                 | 3 頂点 `shape.lineTo()`                      |    |
    | CIRCLE                   | `ShapeUtils.ellipse()` または `Path.absarc()` |    |
    | HALF\_CIRCLE, NICHE など複合 | 複数サブパス + `Shape.holes`                     |    |
* 返り値は **Shape**（2D）

---

### STEP 2 押し出して“板”を作る

```js
function extrudePlate(shape, t) {
  const geo = new THREE.ExtrudeGeometry(shape, { depth: t, bevelEnabled: false });
  geo.rotateX(-Math.PI/2);     // Y 軸が厚み
  geo.translate(0, t/2, 0);    // 板中心が原点
  return geo;
}
```

---

### STEP 3 「角ごとの加工」を適用

* コーナー加工（面取り／角Ｒ／欠き取り）は **Shape 時点** で行うと簡単

  * 例：`corner_tl_code` が ROUND\_R → 該当コーナーだけ `quadraticCurveTo`
  * `TRIANGLE` や `CIRCLE` は Corner 無視で OK

---

### STEP 4 丸穴・四角穴を CSG で削る

1. `ctx.holes_round = [{x,z,dia}, …]`
2. `ctx.holes_square = [{x,z,w,h}, …]`
3. `applyRoundHoles(baseMesh, ctx)`／`applySquareHoles(baseMesh, ctx)`

   * CylinderGeometry / BoxGeometry を `Group` にまとめて `CSG.subtract`

---

### STEP 5 断面加工（各辺）

* 断面面取り (Chamfer) ＝ バイアス付き Box を `CSG.subtract`
* 断面Ｒ ＝ 半円シリンダを `CSG.subtract`
* 段欠き・溝 ＝ Box を subtract / add

必要になった順に
`applyEdgeChamfer`, `applyEdgeRound`, `applyRabbet` … と helpers を増やす

---

### STEP 6 マテリアル・塗装

* `material_code` → **木目テクスチャ** / 単色をロード
* `paint_type_code / paint_surface_code` で

  * `material.color.setHex(…)`
  * `material.metalness/roughness` 調整

---

### STEP 7 Stimulus パイプライン

```js
mesh = new THREE.Mesh( extrudePlate(buildBaseShape(ctx), ctx.t), material )
mesh = applyCornerModifiers(mesh, ctx)   // (面取りなど平面加工済みならスキップ可)
mesh = applyRoundHoles(mesh, ctx)
mesh = applySquareHoles(mesh, ctx)
mesh = applyEdgeMachining(mesh, ctx)
scene.add(mesh)
```

* **再描画時** は旧メッシュを `scene.remove(old)` → `dispose()` → 追加

---

### STEP 8 性能・UX 仕上げ

* 操作毎に **デバウンス 200 ms** を入れて CSG 連打を防ぐ
* ポリゴン数が 5 千超えたら `BufferGeometryUtils.mergeVertices()` → `geo.computeVertexNormals()`
* カメラ操作は `OrbitControls`。必要なら `controls.enableDamping = true`

---

## まとめ

* **RoundedBoxGeometry は不要**
  → **Shape + Extrude + CSG** で一貫
* 実装は **「形状 → 押し出し → 穴 → 断面加工」** のレイヤ構造
  → 追加機能は Helper 関数を足すだけで拡張可能
* Three.js core + three-csg-ts で充分。将来重くなったら three-mesh-bvh を検討

この段取りで進めれば、UI で選んだあらゆる設定を 3D プレビューへ確実に反映できます。

# absarc(cx, cy, r, start, end, clockwise)  

| 引数          | 意味            | 注意点                              |
| ----------- | ------------- | -------------------------------- |
| `cx, cy`    | 円弧の **中心座標**  | 三角関数の原点                          |
| `r`         | **半径**        | 単位は同じ（mm なら mm）                  |
| `start`     | **開始角**（ラジアン） | 0 rad は “+X 方向”                  |
| `end`       | **終了角**（ラジアン） | 角度は全て **反時計回りが正**                |
| `clockwise` | **描画方向**      | `true` → 時計回り<br>`false` → 反時計回り |

角度はラジアン

* 0 rad … +X 方向
* π/2 rad … +Y 方向
* π (=180°) rad … –X 方向
* –π/2 (-π/2) rad … –Y 方向

```js
import * as THREE from "three";
import { BufferGeometryUtils } from "three/examples/jsm/utils/BufferGeometryUtils.js";

/* -------- 1. プロファイル: Y=1 mm の極細三角形 (ローカルXZ断面) -------- */
const profShape = new THREE.Shape();
profShape.moveTo(0, 0);
profShape.lineTo(0, 1);
profShape.lineTo(1, 0);
profShape.closePath();

// Extrude:   depth=1 → ローカル Y=1 mm のストリップ
const protoGeo = new THREE.ExtrudeGeometry(profShape, {
  depth: 1,
  steps: 1,
  bevelEnabled: false,
});

// Z 側へ 0 mm だけ食い込ませる／Y=0〜1 に揃える
protoGeo.translate(0, 0.5, 0);   // （必要に応じて -r だけ Z 方向へずらす）

/* -------- 2. 外周 Path （直線＋円弧＝開いたまま） -------- */
const path = new THREE.Path()
  .moveTo(0, 0)
  .lineTo(100, 0)
  .absarc(100, 100, 100, -Math.PI / 2, 0, false);   // 90°円弧

/* -------- 3. 曲線ごとに「適切な分割点」を生成 -------- */
const STEP = 5;                    // ≒5 mm ピッチで分割
function splitCurve(curve) {
  const div = Math.max(1, Math.ceil(curve.getLength() / STEP));
  return curve.getPoints(div);     // Vector2[]（div+1 個）
}

/* -------- 4. 時計／反時計を判定 → 右側を「内側」に統一 -------- */
function signedArea(arr) {
  let a = 0;
  for (let i = 0; i < arr.length - 1; i++) {
    a += arr[i].x * arr[i + 1].y - arr[i + 1].x * arr[i].y;
  }
  return a / 2;
}
const isCW = signedArea(path.getPoints(1)) < 0;   // true なら時計回り

/* -------- 5. 工具を複製して cutters 配列へ -------- */
const cutters = [];

path.curves.forEach((curve) => {
  const pts = splitCurve(curve);
  for (let i = 0; i < pts.length - 1; i++) {
    const p0 = pts[i];
    const p1 = pts[i + 1];

    // 辺ベクトル v
    const v = new THREE.Vector2().subVectors(p1, p0);
    const len = v.length();
    if (!len) continue;            // ゼロ長をスキップ

    // 「進行方向右側＝内側」になる法線
    const n = isCW
      ? new THREE.Vector2(-v.y, v.x)   // Path が時計回り
      : new THREE.Vector2( v.y,-v.x);  // 反時計なら符号反転
    const ang = Math.atan2(n.y, n.x);

    // --- プロトタイプをクローンして回転・伸長・平行移動 ---
    const g = protoGeo.clone()
      .rotateZ(ang)                     // 向きを揃える
      .scale(1, len, 1)                 // Y=1 → 辺長 mm に
      .translate(
        (p0.x + p1.x) / 2,              // X = 辺中央
        len / 2,                        // Y = 区間中央
        (p0.y + p1.y) / 2               // Z = Vector2 の y → Z
      );

    cutters.push(g);                    // cutters に Geometry を追加
  }
});

/* -------- 6. 全工具を merge して 1 つのジオメトリに -------- */
const cuttersGeo = BufferGeometryUtils.mergeBufferGeometries(cutters, false);
// → cuttersGeo を Mesh にして boardMesh と CSG.subtract すれば完成
```

```js
const path = new THREE.CurvePath();
path.add( new THREE.LineCurve3( new V3(0,   0, 0), new V3(100, 0, 0) ) );
path.add( new THREE.LineCurve3( new V3(100, 0, 0), new V3(100,50, 0) ) );
path.add( new THREE.LineCurve3( new V3(100,50, 0), new V3(0,  50, 0) ) );
path.add( new THREE.LineCurve3( new V3(0,  50, 0), new V3(0,   0, 0) ) );

/* 2. 断面（ローカル XZ）を用意。ここでは幅1×高さ1の三角刃 */
const profile = new THREE.Shape()
  .moveTo(-0.5, 0).lineTo(0.5, 0).lineTo(0, 1).closePath();

/* 3. ExtrudeGeometry で「XY をなぞり、Z 方向へ厚み」を与える */
const thickness = 20;                     // 板の厚み 20 mm
const cutterGeo = new THREE.ExtrudeGeometry(profile, {
  extrudePath  : path,                    // XY の外形
  steps        : Math.ceil(path.getLength()/2),
  bevelEnabled : false
})
.rotateY(Math.PI/2)                       // 刃先面を板側へ
.translate(thickness/2, 0, 0)             // X=0 面を板面に合わせる
.translate( 0.05, 0, 0 );                 // +0.05 mm 食い込ませる（ε）

/* 4. あとは CSG.subtract(baseMesh, new THREE.Mesh(cutterGeo)) */
```

### 🔧 よく使われる Devise モジュール一覧（日本語解説）

| モジュール名                      | 日本語での意味・役割                                                   |
| --------------------------- | ------------------------------------------------------------ |

## Rails で「月次バッチ（月1回実行される処理）」を作る

### ✅ 1. **バッチ本体（rake タスク or Rubyクラス）**

Rails の環境下で処理を行うには、`lib/tasks/` 以下に `.rake` ファイルを作るのが一般的です。

#### 例: `lib/tasks/monthly.rake`

```ruby
namespace :monthly do
  desc "銀行・支店CSVを取り込む"
  task import_bank_data: :environment do
    Rake::Task["bank_data:import"].invoke
  end

  desc "月次処理の全体バッチ"
  task run: :environment do
    puts "=== 月次バッチ開始 ==="
    Rake::Task["monthly:import_bank_data"].invoke
    # 他にも追加したければここに並べる
    puts "=== 月次バッチ終了 ==="
  end
end
```

---

### ✅ 2. **スケジューラでの実行設定（cron, whenever など）**

#### おすすめ: `whenever` gem を使った cron 自動生成

```ruby
# Gemfile
gem 'whenever', require: false
```

```bash
bundle install
```

#### 設定ファイル: `config/schedule.rb`

```ruby
# config/schedule.rb
set :output, "log/cron.log"
set :environment, "production"  # Docker内などで切り替え可

# 毎月1日 03:00 に実行
every '0 3 1 * *' do
  rake "monthly:run"
end
```

#### cronに反映（※host側で）

```bash
# 通常
whenever --update-crontab

# Dockerでroot cronを設定したいときは調整が必要
```

---

### ✅ 3. **Docker環境への組み込み（手動 or cronで）**

#### 手動で実行するなら：

```bash
docker compose exec app bin/rails monthly:run
```

#### 自動化（cron/docker cron）したいなら：

* Dockerfileに `cron` をインストールし、
* `cron` を起動する専用サービスを `docker-compose.yml` に追加する
* または `sidekiq-scheduler` を使うのも選択肢

---

### ✅ 代替：`ActiveJob` + `sidekiq-scheduler`

もし既に Sidekiq を導入している場合は `sidekiq-scheduler` を使って定時実行するのも安定です。GUIで管理もできて便利です。

* `lib/tasks/monthly.rake` に処理を記述
* `bin/rails monthly:run` でいつでも手動実行可能

## ✅ 「板材」と「棒材」の定義をまず整理

| 分類     | 用途               | 一般的な形状                    |
| ------ | ---------------- | ------------------------- |
| **板材** | 棚板・背板・天板・扉など     | **幅・高さが広く、厚みは比較的小さい**（平面） |
| **棒材** | 棚柱・脚・枠材・フレーム・桟など | **長さがあり、断面は小さい**（細長い立体）   |

## 📏 サイズ制限（バリデーション例）

### 🟦 板材（板状の材料）

| 項目    | 制限値          | 備考              |
| ----- | ------------ | --------------- |
| 幅（W）  | ≦ **1000mm** | 机・棚板に必要なサイズまで対応 |
| 高さ（H） | ≦ **2000mm** | 一般的な3×6板相当      |
| 厚み（T） | ≦ **30mm**   | 加工機・重量面の上限      |

```ruby
# 例：板材用バリデーション
validates :width, numericality: { less_than_or_equal_to: 1000 }
validates :height, numericality: { less_than_or_equal_to: 2000 }
validates :thickness, numericality: { less_than_or_equal_to: 30 }
```

---

### 🟫 棒材（角棒や丸棒など）

| 項目          | 制限値          | 備考                    |
| ----------- | ------------ | --------------------- |
| **長さ（L）**   | ≦ **2000mm** | 最大サイズ（エレベーター搬入も想定）    |
| **断面幅（W）**  | ≦ **100mm**  | 大きすぎると重量・加工負荷が増大      |
| **断面高さ（H）** | ≦ **100mm**  | ＝ 断面が 100×100mm までが目安 |

```ruby
# 例：棒材用バリデーション
validates :length, numericality: { less_than_or_equal_to: 2000 }
validates :cross_section_width, numericality: { less_than_or_equal_to: 100 }
validates :cross_section_height, numericality: { less_than_or_equal_to: 100 }
```

※ Rails上は共通モデルにして、`material_type: '板材' or '棒材'` でバリデーション分岐させても良いですね。

## ✅ 四角穴における安全距離の考え方

### 1. **穴同士の距離**

* **安全距離＝外接円の直径ベース**
* 四角形の**対角線の長さ ÷ 2 ≒ 外接円半径**と考え、
  そこから穴と穴の**最短距離（エッジ同士）が空いていればOK**

#### 👉 安全距離（中心～中心の最小距離） ≧ `sqrt(w² + h²) + マージン`

| 穴サイズ例    | 外接円直径   | 安全中心間距離の目安   |
| -------- | ------- | ------------ |
| 5×5 mm   | 7.1 mm  | **12〜14 mm** |
| 8×8 mm   | 11.3 mm | **16〜18 mm** |
| 10×20 mm | 22.4 mm | **28〜30 mm** |

> 📌 **マージン（+5mm前後）を加えるのが推奨**

---

### 2. **端からの距離**

* 四角穴の**最も近い辺と端面との距離**が重要
* 端からの距離は、**短辺のサイズ × 1.0〜1.5倍以上**が目安

| 穴サイズ     | 最小端面距離（目安）   |
| -------- | ------------ |
| 5×5 mm   | **5〜7 mm**   |
| 8×8 mm   | **8〜12 mm**  |
| 10×20 mm | **10〜15 mm** |

> 📌 **木材の繊維方向（縦目・横目）によって割れやすさが違うため、やや広めに設定するのが無難**

## ✅ おまけ：AABB（Axis-Aligned Bounding Box）での交差チェック

四角穴は**2D矩形の座標データがある**なら、以下のように判定可能です：

```js
function isOverlapping(rect1, rect2) {
  return !(
    rect1.x + rect1.width  <= rect2.x ||
    rect2.x + rect2.width  <= rect1.x ||
    rect1.y + rect1.height <= rect2.y ||
    rect2.y + rect2.height <= rect1.y
  )
}
```

## ✅ 材種が違っても統一感を出せる理由と条件

| 項目                | 内容                                        |
| ----------------- | ----------------------------------------- |
| **塗装の種類**         | オイル・ステイン・ウレタンなど、**着色＋保護**の塗料を選ぶことで統一感を出せる |
| **表面処理（研磨）**      | 材種ごとの吸い込みを均一にするため、**しっかりサンディング**することが重要   |

| **集成材 vs 無垢材の違い** | 木目の出方に多少違いはあるが、**濃い色で塗ればあまり目立たない**        |

## 💡 日本語の例

```js
function makeTextSprite(text) {
  const canvas = document.createElement('canvas');
  const context = canvas.getContext('2d');

  const fontSize = 48;
  context.font = `${fontSize}px sans-serif`; // 日本語も描ける
  const textWidth = context.measureText(text).width;

  canvas.width = textWidth + 20;
  canvas.height = fontSize + 20;

  context.font = `${fontSize}px sans-serif`;
  context.fillStyle = 'white';
  context.textAlign = 'center';
  context.textBaseline = 'middle';
  context.fillText(text, canvas.width / 2, canvas.height / 2);

  const texture = new THREE.CanvasTexture(canvas);
  const material = new THREE.SpriteMaterial({ map: texture, transparent: true });
  const sprite = new THREE.Sprite(material);
  sprite.scale.set(50, 25, 1);

  return sprite;
}

scene.add(makeTextSprite('横').position.set(150, 0, 0));
scene.add(makeTextSprite('縦').position.set(0, 150, 0));
scene.add(makeTextSprite('奥').position.set(0, 0, 150));
```

## 解釈としては次を前提にします：

* 弦の端点：A₁(Ax1, Ay1)、A₂(Ax2, Ay2)
* 矢高の線分：B₁(Bx1, By1)（弦上の足）→ B₂(Bx2, By2)（円弧上の先端）

このとき、**3点 A₁・A₂・B₂ を通る円**が一意に定まり、その円の中心が求まります（3点が一直線でない限り）。B₁は「矢高が弦に垂直かの検証」に使えますが、中心計算自体は A₁・A₂・B₂ の3点で十分です。

---

# 解法A（汎用：3点から円の中心）

3点 $P_1(x_1,y_1)=A_1$, $P_2(x_2,y_2)=A_2$, $P_3(x_3,y_3)=B_2$ に対して、中心 $(u_x,u_y)$ は

$$
D = 2\Big[x_1(y_2-y_3)+x_2(y_3-y_1)+x_3(y_1-y_2)\Big]
$$

$$
u_x=\frac{
 (x_1^2+y_1^2)(y_2-y_3) + (x_2^2+y_2^2)(y_3-y_1) + (x_3^2+y_3^2)(y_1-y_2)
}{D}
$$

$$
u_y=\frac{
 (x_1^2+y_1^2)(x_3-x_2) + (x_2^2+y_2^2)(x_1-x_3) + (x_3^2+y_3^2)(x_2-x_1)
}{D}
$$

* もし $D=0$（3点がほぼ一直線）だと円は定まりません。

### Ruby実装（Railsでもそのまま使えます）

```ruby
def circle_center_from_three_points(x1, y1, x2, y2, x3, y3)
  d = 2.0 * (x1 * (y2 - y3) + x2 * (y3 - y1) + x3 * (y1 - y2))
  raise ArgumentError, "3点が一直線で中心を求められません" if d.abs < 1e-12

  ux = ((x1**2 + y1**2) * (y2 - y3) +
        (x2**2 + y2**2) * (y3 - y1) +
        (x3**2 + y3**2) * (y1 - y2)) / d

  uy = ((x1**2 + y1**2) * (x3 - x2) +
        (x2**2 + y2**2) * (x1 - x3) +
        (x3**2 + y3**2) * (x2 - x1)) / d

  [ux, uy]
end

# 使い方（A1,A2,B2の順に渡す）
ux, uy = circle_center_from_three_points(Ax1, Ay1, Ax2, Ay2, Bx2, By2)
```

---

# 解法B（B₁が弦の**中点**で、B₁→B₂が弦に**垂直**＝純粋な「矢高 h」）

この特別ケースなら従来の矢高公式が使えます。

1. 弦の中点 $M$、長さ $L$：

$$
M=\Big(\tfrac{Ax1+Ax2}{2},\ \tfrac{Ay1+Ay2}{2}\Big),\quad
L=\sqrt{(Ax2-Ax1)^2+(Ay2-Ay1)^2}
$$

2. 矢高 $h=\pm\|B_2-B_1\|$（弦に垂直方向を正負で取り扱い）

3. 半径

$$
R=\frac{L^2}{8h}+\frac{h}{2}
$$

4. 弦に垂直な単位ベクトル $\vec n$ を使い、
   中心 $C = M \pm a\,\vec n$、ただし

$$
a=\sqrt{R^2-(L/2)^2}
$$

---

# 実務メモ

* \*\*入力が「弦2点＋矢高線分の2点」\*\*で来る場合、まず B₁ が弦上で、B₁→B₂ が弦に垂直かをチェックすると安心です。
  垂直でなければ「矢高」としては不整合ですが、**A₁・A₂・B₂ の3点円**としては依然計算できます。
* 幾何誤差で $D\approx 0$ になることがあるので、しきい値（例：1e-12）で判定してください。

必要なら、上の Ruby を Stimulus から API 経由で叩けるように小さなエンドポイントも用意します。サンプルの JSON I/F も書けますよ。

# 3) Strong Parameters（許可 & サニタイズ）

* ハッシュの中身をしっかり許可する
* `proc` が空（= 未加工）の角は **キーごと削除**
* `dx/dy` は数値に整形（空なら `nil`）

```ruby
def board_part_params
  p = params.require(:board_part).permit(
    # 他の属性…
    corner_json: {
      tl: %i[proc dx dy],
      tr: %i[proc dx dy],
      bl: %i[proc dx dy],
      br: %i[proc dx dy]
    }
  )

  # --- サニタイズ ---
  if (cj = p[:corner_json]).present?
    cj.transform_values! { |h| (h || {}).to_h }                # nil防御
    cj.each do |corner, h|
      # 空文字→nil、数値化
      h["proc"] = h["proc"].presence
      %w[dx dy].each { |k| h[k] = h[k].present? ? h[k].to_f : nil }
    end
    # proc が無い（=未加工）角は削除
    cj.select! { |_corner, h| h["proc"].present? }
    p[:corner_json] = cj
  end

  p
end
```

# 4) モデル（デフォルト & 任意バリデーション）

```ruby
class BoardPart < ApplicationRecord
  attribute :corner_json, :json, default: -> { {} }

  # 例: proc がある角は dx/dy も必須・0以上
  validate :validate_corner_json

  private

  def validate_corner_json
    (corner_json || {}).each do |corner, h|
      next if h.blank?
      if h["proc"].present?
        errors.add(:corner_json, "#{corner}: dx必須") if h["dx"].nil?
        errors.add(:corner_json, "#{corner}: dy必須") if h["dy"].nil?
        if h["dx"].to_f < 0 || h["dy"].to_f < 0
          errors.add(:corner_json, "#{corner}: dx/dy は0以上")
        end
      end
    end
  end
end
```

これで「未加工の角は保存しない」「指定した角だけ `{corner: {proc,dx,dy}}` を保存」という要件を満たせます。
`side_json` / `edge_json` も同じパターンでテンプレ化できますよ。  

* `h = (@board_part.corner_json || {}).dig(key.to_s) || {}` で、
  たとえば `key = :tl` のとき `h` は `{"proc"=>"chamfer","dx"=>3.0,"dy"=>3.0}` になります。
* `options_for_select(corner_proc_options, h["proc"])` の **第2引数が選択値** なので、
  `h["proc"]` が `"chamfer"` なら、`value="chamfer"` の option が選択状態で描画されます。
* `tr` / `bl` などその角が無い場合は `h` が `{}` になるので、**未選択**（またはブラウザ既定）になります。

補足ポイント

* JSONBは通常**文字列キー**で返るので、`h["proc"]` でOK（あなたのコードのままで大丈夫）。
  もしアプリ側で `deep_symbolize_keys` などをして**シンボル化**しているなら、`h[:proc]` に変えてください。
* 数値入力も同様に `number_field_tag ..., h["dx"]` / `h["dy"]` で値が入ります。
* 「未加工」を空文字 `""` にしているなら、未指定の角は**何も選択されない**（= ブラウザが先頭を表示）挙動になります。必ず空を明示的に選ばせたいなら、`prompt: "選択してください"` を付ける選択肢もあります。

## ✅ `scene.add()` で独立した `Mesh` はいくつでも出し入れできます。ポイントは\*\*消すときの後始末（GPUリソース解放）\*\*だけ。

## 実務チェックリスト

* 画面から消す → `scene.remove(mesh)`（これだけで次フレームから描画されない）
* メモリも解放 → `mesh.geometry.dispose()` / `mesh.material.dispose()`（テクスチャがあれば `texture.dispose()` も）
* **共有リソースに注意**：同じ `geometry` / `material` / `texture` を他の Mesh も使っているなら **dispose しない**（必要なら `clone()` で分ける）
* 付随オブジェクト（`EdgesGeometry` 等）は **`mesh.add(edges)` で子にすると一緒に外れる**（処理が楽）
* ループしていない構成なら、**変更後に `renderer.render(scene, camera)` を1回**呼ぶ
* 頻繁に表示/非表示を切り替えるだけなら **`mesh.visible = false/true`** で済ませるのも手（再add/removeやdispose不要）
* マテリアルはできれば**使い回し**、描画モードを変えるときだけ `material.needsUpdate = true`

## まとめ関数（短版）

```js
function removeAndDispose(scene, root) {
  if (!root) return
  scene.remove(root)
  root.traverse(o => {
    o.geometry?.dispose?.()
    const mats = Array.isArray(o.material) ? o.material : [o.material]
    mats.forEach(m => {
      if (!m) return
      // m.map などテクスチャ類も解放
      Object.values(m).forEach(v => v?.isTexture && v.dispose())
      m.dispose?.()
    })
  })
}
```

これを使えば、**片方だけ残す／全部消す**の制御が安全にできます。
