# ezdxf チートシート（日本語）

> DXF を **Python** で読み書きするための実用サマリ。
> 例は互換性重視の **R12 + mm（$INSUNITS=4）** 前提です。

---

## 0) インストール

```bash
pip install ezdxf pymupdf  # （PDF/PNG化に PyMuPDF を使う場合）
```

---

## 1) 図面の基本

```python
import ezdxf
from io import StringIO

# 新規作成（互換性重視なら R12、機能を増やすなら R2000 以降）
doc = ezdxf.new("R12", setup=True)      # R12 / R2000 / R2007 ... など
doc.header["$INSUNITS"] = 4             # 4 = mm（単位の明示）
# R12を明示したいとき（通常は new("R12") で十分）
doc.header["$ACADVER"] = "AC1009"       # AC1009 = R12

msp = doc.modelspace()                  # Model Space を取得
```

### DXF 版コードの目安

* `AC1009` = R12
* `AC1015` = R2000
  （R12 は互換性◎、ただし機能は少なめ）

### 単位 `$INSUNITS`

* `0` 未定義, `1` inch, `4` mm, `6` m …
  （mm 運用なら **4** を固定推奨）

---

## 2) レイヤ

```python
doc.layers.new("OUTER", dxfattribs={"color": 1})  # 赤
doc.layers.new("DRILL", dxfattribs={"color": 5})  # 青
doc.layers.new("TEXT",  dxfattribs={"color": 7})  # 白
```

* CAM 連携では **レイヤ名の規約**が重要（例：`OUTER`, `DRILL`）。

---

## 3) エンティティの追加

### 線・円・ポリライン

```python
# 直線
msp.add_line((0, 0), (100, 0), dxfattribs={"layer": "OUTER"})

# 円
msp.add_circle((20, 20), 3, dxfattribs={"layer": "DRILL"})

# 軽量ポリライン（推奨）
pl = msp.add_lwpolyline(
    [(0,0), (100,0), (100,50), (0,50)],
    dxfattribs={"layer": "OUTER"}
)
pl.closed = True  # 閉領域にする
```

> **LWPOLYLINE の円弧**は **bulge** で表現（頂点タプルの5番目）。
> CAM 側の都合で bulge 禁止なら **ARC に展開**して出力を。

### テキスト（位置は `insert`）

```python
msp.add_text("板 100x50", dxfattribs={
    "height": 3.5,             # 文字高さ
    "layer": "TEXT",
    "insert": (0, -10),        # ここが位置（左下基準）
})
```

---

## 4) 寸法（DIMENSION）

```python
# 線形寸法（水平/垂直）
dim = msp.add_linear_dim(
    base=(50, -10),            # 寸法線のベース位置（オフセット）
    p1=(0, 0), p2=(100, 0),    # 寸法の始点・終点
    dimstyle="EZDXF"           # 既定の寸法スタイル
)
dim.render()                    # ← 必須！ ブロック生成して表示可能にする

# 斜め（aligned）の例
# msp.add_aligned_dim(p1=(0,0), p2=(100,50), distance=10).render()
```

* **`render()` を忘れると図面上に見えません**（定番ハマりポイント）。
* 既定のスタイルは `EZDXF`。見栄え調整は DIMSTYLE をカスタム。

---

## 5) 監査（Audit）

```python
aud = doc.audit()
if aud.errors:
    for e in aud.errors:
        print("[AUDIT]", e)
```

* DXF の構造エラーがあればここに集まる。生成直後に回すのがおすすめ。

---

## 6) 書き出し（ファイル or メモリ）

### ファイルへ保存

```python
doc.saveas("out.dxf")
```

### メモリ（バイト列）で取り出す（Web API など）

```python
buf = StringIO()
doc.write(buf)                  # DXF テキストを出力
dxf_bytes = buf.getvalue().encode("utf-8")  # bytes に
```

> `BytesIO` を使うと `str`/`bytes` でエラーになりがち。**DXFはテキスト**なので `StringIO` → `encode` が安全。

---

## 7) 読み込み・編集

```python
doc = ezdxf.readfile("in.dxf")
msp = doc.modelspace()

# 走査例
for e in msp:
    t = e.dxftype()            # "LINE", "LWPOLYLINE", "CIRCLE", ...
    if t == "LWPOLYLINE":
        print(list(e.get_points("xy")))   # [(x,y), ...]
    elif t == "LINE":
        print(e.dxf.start, e.dxf.end)
```

## 8) PDF/PNG への描画（レンダリング）

> 公式の **drawing アドオン**でも描けますが、現状は

```python
import fitz

def dxf_to_pdf_bytes(doc, mm_per_unit=1.0) -> bytes:
    # 既存の自作関数を利用してOK（あなたの環境に合わせる）
    ...

def pdf_to_png(pdf_bytes: bytes, width_px=1000) -> bytes:
    pdf = fitz.open(stream=pdf_bytes, filetype="pdf")
    page = pdf[0]
    zoom = width_px / page.rect.width
    mat = fitz.Matrix(zoom, zoom)
    pix = page.get_pixmap(matrix=mat, alpha=False)
    return pix.tobytes("png")
```

## 9) CAM 用 DXF の注意（実務）

* **エンティティ制限**：`LINE / LWPOLYLINE / CIRCLE / ARC` のみに（`TEXT/MTEXT/DIMENSION/HATCH/SPLINE/BLOCK` は原則禁止）
* **閉領域**：外形（OUTER）は閉ポリライン化、0長さ線や重複線を除去
* **単位/版**：`$INSUNITS=4`（mm）明示、慣例的に **R12** が無難
* **bulge**：CAM によっては不可 → `ARC` に展開するポリシーを
* **レイヤ命名**：`OUTER`, `DRILL` など、業者と取り決め
* **監査**：生成後に `doc.audit()` を通し、NGなら返さない

---

## 10) よくあるエラーと対処

* **`'Text' object has no attribute 'set_pos'`**
  → 位置は `entity.dxf.insert = (x, y)` か `add_text(..., dxfattribs={"insert": (...)})`。

* **寸法が見えない**
  → `add_linear_dim(...).render()` を忘れている。

* **`a bytes-like object is required, not 'str'`**
  → `doc.write()` の出力は **テキスト**。`StringIO` で受けてから `encode("utf-8")` する。

* **PDF/PNGで日本語が□になる**
  → コンテナにフォント（`fonts-dejavu-core`,`fonts-noto-cjk` など）を入れる。

## 11) スニペット（外形＋穴＋寸法の最小例）

```python
import ezdxf
from io import StringIO
doc = ezdxf.new("R12", setup=True)
doc.header["$INSUNITS"] = 4
msp = doc.modelspace()

doc.layers.new("OUTER", dxfattribs={"color": 1})
doc.layers.new("DRILL", dxfattribs={"color": 5})
doc.layers.new("TEXT",  dxfattribs={"color": 7})

pl = msp.add_lwpolyline([(0,0),(100,0),(100,50),(0,50)], dxfattribs={"layer":"OUTER"})
pl.closed = True
msp.add_circle((20,20), 3, dxfattribs={"layer":"DRILL"})

msp.add_text("板 100x50", dxfattribs={"height":3.5, "layer":"TEXT", "insert":(0,-10)})

dim = msp.add_linear_dim(base=(50,-10), p1=(0,0), p2=(100,0), dimstyle="EZDXF")
dim.render()

buf = StringIO(); doc.write(buf)
dxf_bytes = buf.getvalue().encode("utf-8")
```

---

## 12) 用語メモ

* **Model Space / Paper Space**：実体を描くのは通常 **Model Space**。
* **Bulge**：LWPOLYLINE 頂点に付く円弧量（`tan(θ/4)`）。禁止なら `ARC` へ分解。
* **DIMSTYLE**：寸法スタイル（文字サイズ、矢印形状など）。

# おすすめ料金設計（ざっくり）
「価値＝手間＆責任の大きさ」に合わせて、**DXF / PDF / ops.json ＝中立の“注文パッケージ”生成は無料**、**NC生成以降＝機種依存＋責任重い＝有料**が合理的。
* **Free（Builder）**

  * DXF（R12・mm・レイヤ規約固定）
  * PDF（フッターにウォーターマーク）
  * `ops.json`（中立スキーマ v1）出力
  * プレビュー（SVG/PNG）
  * 1日N件 or 月間上限、ストレージは7日で自動削除
* **Pro（Shop）**

  * ウォーターマークなし、履歴保存、ZIP一括（DXF/PDF/ops.json）
  * ベンダープロファイルの保存（既定テンプレ × 業者別微調整）
  * 自動バリデーション（外形閉路チェック、最小穴径、レイヤ整合）
  * APIキー・Webhook、チーム共有、優先キュー
* **Add-on: NC Pack（機種別）**

  * ポスト処理（FANUC系3軸→他へ拡張）
  * 機種プロファイル（小数桁、G98/G99、M29要否…）
  * ツール/材料テーブル、簡易シミュレータ連携、SLA
  * 価格は**“1機種ごと／月”＋初期オンボーディング費**が現実的

## 技術的な線引き（将来拡張しやすく）

* **ops.json は機種中立**：`version` と `features[]` を明示（semver）
* **ポストはプラグイン**：`PostFANUC`, `PostSiemens`…で吸収、機種差はYAMLで切替
* **PDFはHTML→PDF**（Grover/WickedPDF か WeasyPrint）
* **出力一式の命名規約**：`<part>_<rev>_<kind>.<ext>`、ZIPに `manifest.json` と `checksum`

## まず無料版で“安定出力”に必要なチェック

* DXF：R12／`$INSUNITS=4`／`OUTER, DRILL` 以外禁止／閉路・重複線・自己交差の自動検査
* PDF：穴テーブル・基準面（A/B/C）・注記（面取り/公差）
* ops.json：スキーマ検証（必須項目、不正値、範囲）
* 失敗時は**警告と直し方**を返す（Upgrade誘導は控えめに）

## アップグレード動機に効く機能

* **ZIP一括DL**、**履歴＆再発行**、**API/Webhook**
* **ベンダープロファイル**（面別DXFやラベル仕様）保存
* **自動バリデーションの詳細レポート**（PDF添付）
* **バッチ処理**（CSV/JSONインポート → 一括生成）

# 業界全体のCNCルータ保有率

ざっくり言うと、「業界全体の“CNCルータ保有率”」を正面から示す公的統計は見当たりません。政府統計は“どれだけの事業所が CNC ルータを持っているか”までは取っておらず、木材系では事業所数や出荷額などの集計が中心です。例えば 2023 年時点での事業所数は、

* 木材・木製品製造業（家具を除く）…6,235 事業所
* 家具・装備品製造業 …6,378 事業所
  合計で約 1.26 万事業所（個人経営除く）です。

一方で、CNC ルータの市場規模を見ると、日本市場の売上は 2024 年で約 3,560 万ドル規模という推計があり、年率 7.6% 前後で伸びる見込みとされています（産業横断の推計で、木工用途に限定しない概況）。([グランドビューリサーチ][1])
また、産業用 CNC ルータは新品で“数百万円～数千万円”が一般的な価格帯という解説もあり、導入の初期コストが小規模事業所にはハードルになりがちです。([切削加工機メディア～切削ナビ～][2])

この2点（①対象業種の事業所数が多い、②機械の価格が高い）を踏まえると、**木材関連の事業所“全体”で見たときは、非保有が多数派**と見るのが現実的です。逆に、**対象を「看板・内装・店舗什器・造作家具などで2D曲線カットを常用する中規模以上」へ絞ると、保有（自社 or 提携先）がかなり増える**、というのが実務感覚に近いところです（ただし比率の正確な数値は公開されていません）。

### 実務に落とすなら

比率そのものより、マッチング時に以下の“能力タグ”で切る方が有効です。

* **設備**：CNCルータ（有/無）、テーブル有効寸法、最小ビット径/刃長、真空テーブルの有無
* **対応素材**：合板/MDF/集成材/樹脂/アルミ複合板 など
* **精度と面品質**：面粗さ・許容差・バリ/毛羽の後処理可否
* **入稿**：DXF（mm/レイヤ規約）可、曲線（NURBS/スプライン）可、PDF仕様読解可

こうして“CNC あり系”と“直線専用（パネルソー・ビームソー・バンドソー中心）”を最初から分けて募集すれば、実務上は比率を気にせずに最適化できます。

#### 補足（データの取り方）

今後もし比率を把握したければ、

1. 上記の設備アンケートを御社のベンダ登録時に必須化、
2. 主要県の業界団体名簿＋自社登録データを突合して標本化、
